# Временный стенд UI — 17 ноября 2026

Бэкенд: `https://system.buh-profit.com/ui-preview`

Проверка: `GET /ui-preview/health`. В клиенте указывается базовый адрес без
`/health`. Запуск с предзаполненным адресом: `MessengerDesktop --server URL`.
Если сохранённая сессия относится к другому адресу, она не используется.

Стенд изолирован от других приложений Profit и основной БД мессенджера:

- Docker-контейнер `messenger-ui-preview`, образ `messenger-ui-preview:theme-sharing`.
- Слушает только `127.0.0.1:18796`; HTTPS и WebSocket идут через nginx.
- Файлы развёртывания: `/opt/messenger-ui-preview`.
- SQLite и вложения: отдельный Docker volume `messenger-ui-preview-data`.
- Ключ шифрования сгенерирован на сервере в `runtime.env` с правами 0600.
- `MESSENGER_DEV_SEED=false`: демонстрационные аккаунты не создаются.
- Пользователь контейнера 1654, файловая система образа read-only, отдельный
  tmpfs, без Linux capabilities; память 384 MiB, CPU 0.75, PID 128.
- Журнал контейнера ограничен 2 × 5 MiB. Access log для этого временного
  location выключен, чтобы не записывать WS session token в query string.

Nginx подключает `/etc/nginx/snippets/messenger-ui-preview.conf` в TLS server
`system.buh-profit.com`. Проверка `nginx -t` выполнена до reload.
Первоначальная конфигурация сохранена внутри каталога стенда.

## Обратимая остановка

```sh
docker stop messenger-ui-preview
```

Возобновление: `docker start messenger-ui-preview`. База и ключ сохраняются.
Чтобы закрыть публичный маршрут, удалите только include этого стенда из
конфигурации нужного server, выполните `nginx -t`, затем reload. Не заменяйте
всю конфигурацию старой резервной копией: другие приложения могли измениться.

Полное удаление контейнера/тома/ключа — отдельная операция после завершения
проверки командой. Автоматического срока удаления у стенда нет.

Проверены через публичный HTTPS: health, регистрации, личные и групповые чаты,
WebSocket, обмен темами, PATCH и удаление публикации. Аккаунты этого стенда
независимы от аккаунтов основного сервера.
