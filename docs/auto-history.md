# Автоматическая подгрузка истории

При открытии чата загружаются последние 50 сообщений. Когда до верхнего края
остаётся не более 180 пикселей, клиент запрашивает следующую страницу через
`before_id`. Кнопка «Показать раньше» заменена индикатором «Загрузка истории…».

Позиция видимого сообщения сохраняется, в том числе при прокрутке во время
запроса и изменении разделителей дат. История не очищается при добавлении страницы.
Загрузка не блокирует ввод и отправку сообщений. Одновременно выполняется один
запрос истории; смена чата и переход к закрепу отменяют предыдущий запрос.
После сетевой ошибки следующая прокрутка вверх повторяет запрос.

Входящие сообщения прокручивают чат вниз, только если пользователь уже находится
у конца переписки. Открытие чата и отправка своего сообщения переводят к последним
сообщениям. Короткая/пустая страница завершает подгрузку.

## Проверка

Из корня репозитория:

```powershell
dotnet build desktop/MessengerDesktop.csproj -c Release
dotnet run --project tests/DesktopHistoryChecks/DesktopHistoryChecks.csproj -c Release
```

Проверки запускают настоящий `ShellView` в Avalonia Headless и локальный тестовый
HTTP/WebSocket-сервер. Основной backend, база данных и аккаунты не нужны.
Проверяются порядок и полнота истории, сохранение позиции и выделения, отсутствие
дублирующих запросов, задержки и ошибки сети, переключение чатов, входящие сообщения,
переход к старому закрепу во время загрузки и завершение истории при размере,
кратном 50. Проверки также включены в GitHub Actions.

Для ручной проверки откройте чат с более чем 100 сообщениями, прокрутите вверх
несколько раз и проверьте, что видимый текст остаётся на месте. Во время чтения
истории отправьте сообщение со второго клиента; затем вернитесь вниз и повторите.
