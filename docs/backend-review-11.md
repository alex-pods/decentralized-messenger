# Ревью PR #11

Проверен исходный commit `7fed823`. Пять проблем воспроизведены изолированными тестами **до** исправлений; исправления входят в версию 4.1.1.

| Приоритет | Воспроизведённая проблема | Исправление |
| --- | --- | --- |
| P1 | Занятый WS-писатель возвращал кадр в ту же очередь; цикл мог вращаться без ожидания, менять порядок и молча терять кадры при заполнении | Асинхронное ожидание send-lock с таймаутом; закрытие использует тот же lock и `CloseOutputAsync`, без второго параллельного Receive |
| P1 | Ошибка DELETE группы после удаления последнего участника оставляла группу без owner | Удаление членства и группы в одной транзакции; физические вложения удаляются после commit |
| P1 | Обычный старый файл, начинающийся с `MSGFILE1\0`, принимался за шифрованный и останавливал миграцию | Явный режим исходного формата и журнал файлов: исходный защищённый hash, pending/completed; проверено возобновление до и после атомарной замены |
| P2 | Отказ INSERT второго вложения возвращал 500, но оставлял первое в БД и на диске | Транзакция для всего пакета, компенсационное удаление созданных файлов, события только после commit |
| P2 | Каждый обычный перезапуск читал все файлы и запускал VACUUM всей БД | Сохранённая отметка завершения; сканирование и уплотнение только при миграции, обработка bio/отпечатков ограниченными пакетами |

Проверки добавлены в CI: `tests/BackendChecks`, `backend/tests/review_regressions.py`, `backend/tests/deployment_regressions.py`. Интеграционный сценарий и desktop self-check также проходят. Дополнительно проверены нормальный WS close-handshake и отсутствие гонки close/send. При ошибке хранилища запуск завершается кодом 1, до приёма запросов, без необработанного аварийного завершения процесса.

Миграция `005_storage_file_migration` добавочная; первые четыре миграции не изменялись. На сервере проверено обновление копии уже зашифрованной БД 4.1.0 с копией ключей: целостность, число строк, шифрованные поля и байты всех 19 файлов сохранены. Повторный запуск работает. Рабочие данные при проверке копии не менялись и не покидали сервер.

Скрипт развертывания проверяет не только версию, но и точный Git revision в `/health`; ограничивает время HTTP-проверки, запрещает параллельные развертывания и обрабатывает SIGINT/SIGTERM. На Linux в временной файловой системе проверены шесть вариантов: исходное приложение как каталог и как symlink, для каждого — успешное обновление, неверный revision и отказ копирования данных. При отказах восстановлены исходные приложение, данные и drop-in, сервис перезапущен. Боевой rollback намеренно не провоцировался.

Формат шифрования текстов и файлов не менялся, ключи не заменялись. Это сохраняет чтение существующих данных. Полноценной атомарности между файловой системой и SQLite нет: при аварии процесса возможны неиспользуемые шифрованные файлы; обработанные ошибки пакета теперь убираются. Защита от администратора сервера, E2EE и поддержка нескольких процессов этими исправлениями не добавляются.
