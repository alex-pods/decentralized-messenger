# Миграция клиента на backend v4 (MVP-рефакторинг)

Контракты: Swagger — `/swagger/index.html`, OpenAPI — `/swagger/v1/swagger.json`,
протокол WS — `GET /ws/protocol`. Версия API: `4.0.0`.

## Таблица изменений

| Было (v3) | Стало (v4) | Правка клиента |
|---|---|---|
| `GET /users/me/settings`, `PATCH /users/me/settings` (`save_history`) | **Удалены** (настройки не осталось) | Убрать экран/вызовы настроек истории. Тексты сообщений теперь всегда сохраняются на сервере |
| Поле `user_session_token` в JSON-телах (logout, отправка, удаление и т.п.) | **Удалено из всех DTO** | Авторизация REST — только заголовок `Authorization: Bearer <token>` |
| REST-авторизация через `X-Session-Token` или `?user_session_token=` | **Не работает (401)** | Перейти на Bearer. WS — по-прежнему `ws://…/ws?user_session_token=<token>` |
| `POST /chats/{id}/messages` — тело `{text, reply_to_id?}` | Добавлено необязательное `client_ref` (до 64 симв.) — идемпотентный ключ **отправителя** | Повтор запроса после сетевого сбоя: тот же `client_ref` + то же содержимое → **200** и прежний `message_id`; тот же `client_ref` с другим содержимым → **409 `client_ref_conflict`**; без `client_ref` поведение прежнее (всегда 201) |
| `content_state`: `stored / not_stored / deleted` | То же поле, но `not_stored` бывает **только у старых сообщений** (текст утрачен, `text:null`); новые — всегда `stored` или `deleted` | Показывать такие записи как «сообщение не сохранено»; новых таких не появится |
| Тексты ошибок в `error` | Значения стали русскими строками; разбор — по машинному `code` (`{code, error, details, trace_id}`) | Если клиент матчит по тексту `error` — перейти на `code` |
| WS-события `member_added` / `member_left` | Теперь доставляются **только по `follow(chat_id)`** (раньше не доставлялись вовсе) | Подписаться на чат, чтобы видеть изменения состава; `owner_changed`, `member_role_changed`, `chat_created` — без подписки, как раньше |
| WS close-коды | Добавлен `4008` — медленный клиент (переполнена очередь доставки 256 событий) | При 4008 — переподключиться и догнать историю через `GET /chats/{id}/messages?before_id=…` |
| `/health` → `version` | `4.0.0` | — |

## Без изменений (проверено сьютом)

Маршруты и semantics: профили и аватары (включая проверку PNG/JPEG/WebP), поиск, личные чаты (единственные на пару, гонко-устойчивые), группы и одинаковый состав, участники/роли/передача владения (`409 owner_transfer_required`), ответы, правка, удаление у всех (`deleted_at`, отзыв вложений) и у себя, реакции, вложения (10 МБ, `413`), история (`limit 1..100`, `before_id`, от старых к новым), прочтения (`read_at` — «все, кроме отправителя»), скрытие чатов, пагинация-ошибки `400` с телом, `415`, `429` c `Retry-After`.

## Тесты

- Функциональный сьют (чёрный ящик): `python backend/tests/blackbox4.py http://<host>/messenger <host> <port>` (последний прогон: 89/89 локально, 85/85 на проде — блок legacy-вставки выполняется только при локальной БД).
- Нагрузочный: `python backend/tests/loadtest.py http://<host>:<port>/messenger [ssh-alias]` — конфигурация в `CONFIG` внутри файла.
